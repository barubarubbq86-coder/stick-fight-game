# 棒人間fight — 3Dバトルシミュレーター

19種類の棒人間を3D戦場へ配置して、自動戦闘を観戦するゲームです。HTML / CSS / JavaScript / WebGL2で動作し、外部ライブラリ・API・広告・課金・個人情報収集はありません。WebGL2対応ブラウザが必要です。

## 遊び方

1. 最初は「フィールド編成」が開きます。おすすめの50対50をそのまま試せます。
2. 「キャラを配置」でTEAM A（青）／TEAM B（赤）と種類を選び、地面をタップ。同じキャラを続けて置けます。
3. 「選択」でキャラ・地形をタップし、「選択したものを移動」で移動先をタップ。「選択を削除」「45°回転」も使えます。
4. 「地形を配置」で小さな丘・大きな丘・岩・壁を置けます。配置時の大きさも選択できます。地形を置かない場所は平地です。
5. 「戦闘開始」を押すと、その位置・向き・地形のまま戦闘が始まります。両チームに1体以上必要です。

丘には高低差があり、キャラもその高さに合わせて移動します。岩・壁は衝突と軽量な経路探索で回避します。岩・壁がキャラと重なる編集は拒否します。射撃の遮蔽や高度な地形物理は今回の対象外です。

「元に戻す」で配置・移動・回転・削除・読込・全消去を最大30操作戻せます。「プリセット保存・読込 / 全消去」を開くと、対象チームや地形を全消去できます。全消去には確認があります。

## クイック編成

「クイック編成」で種類ごとの人数を入力し、「自動配置してフィールドへ」を押すとキャラの布陣を置き換えます。地形は維持します。フィールドで位置を調整してから戦闘開始できます。「元のフィールドへ戻る」は布陣を変更しません。

## プリセットと再戦

「プリセット保存・読込 / 全消去」で名前を入力して保存してください。両チームの種類・位置・向きと地形を、端末のlocalStorageに保存します。同名での上書きはせず、別名を案内します。外部へ送信しません。ブラウザの保存データを消すとプリセットも消えます。

全滅した瞬間に勝敗・HPを確定します。その後約2秒、新たな攻撃と追加配置を止め、飛翔体・吹き飛び・死亡演出を表示してから結果を出します。演出中は既存の飛翔体による追加ダメージも発生しません。神同士だけが残った場合はDRAWです。

「同じ配置でもう一度」は開始前のキャラ配置・地形を復元します。「編成を変更」も開始前の配置を残して編集へ戻ります。戦闘途中の追加キャラは再戦へ引き継ぎません。

## カメラ

- Android: 1本指ドラッグで回転・上下角度。2本指で移動、ピンチでズーム。
- PC: 左ドラッグで回転、右ドラッグまたはShiftドラッグで移動、ホイールでズーム。
- 「ドラッグ：移動」で1本指／左ドラッグの移動も選べます。「全体へ戻る」でカメラをリセット。
- 配置中でも明確なドラッグ・2本指はカメラ操作になり、キャラを置きません。「カメラのみ」ではタップ配置を止めます。

## 戦闘中の追加配置

「キャラを追加配置」でTEAM A／Bと種類を選び、地面をタップすると1体追加します。約0.35秒待って通常AIへ参加します。連続配置でき、「配置終了」で通常操作へ戻ります。一時停止中も配置可能です。勝敗確定後は追加できません。HPバーは現在HP合計／最大HP合計です。追加キャラの最大HPは分母にも加算します。

## GitHub Pages公開

完成ZIPを展開し、中のファイルをすべてリポジトリ直下へアップロードしてください。index.htmlが直下にある構成です。Settings → Pages → Deploy from a branch → main / (root) → Save。公開URLを開けば遊べます。リポジトリ名を含むサブパスにも対応します。

ソースのdistフォルダから公開する場合も、distの中身をリポジトリ直下へコピーしてください。ビルドや外部サーバーは不要です。ES Modulesを使うため、ローカルのHTMLを直接開くfile://ではなくHTTP配信で起動してください。

## Androidへのインストール・オフライン

GitHub PagesのHTTPS URLをChromeで開き、表示される「インストール」、またはChromeのメニューの「ホーム画面に追加」「アプリをインストール」を使ってください。インストール後はstandalone表示で起動します。初回にオンラインでキャッシュ作成を済ませると、ゲーム本体はオフラインでも起動できます。

manifest.jsonのstart_url・scope、sw.jsのパスは相対指定です。更新時はsw.jsのCACHEのバージョンを変更してください。新しい全アセットを保存してから同じリポジトリの旧キャッシュを削除します。更新後はゲームを閉じて再読み込みしてください。

## 拡張用の構造

- data.js: キャラ能力・モデル・当たり判定サイズ・AIタイプ。
- editor.js / FieldEditor: 布陣スナップショット、Undo、ローカルプリセット。
- terrain.js / terrainData / Terrain: 地形定義、heightAt、canOccupy、move、direction。描画とAI、将来のプレイヤー移動で共用できます。
- simulation.js / Character: 移動・攻撃・HP・吹き飛び。AIControllerは指令のみ生成し、setControllerで将来のPlayerControllerへ交換できます。
- render3d.js / Renderer3D: 低ポリゴン・インスタンシング・カリング。SpectatorCameraはキャラから独立し、追従カメラへ交換可能です。

今回、直接操作・複数選択・複雑な地形制作は実装していません。既存キャラのHP・攻撃力・特殊発動率を維持しています。人数に固定上限はありませんが、実際の上限は端末性能によります。

## v4のブラウザ動作確認

ブラウザで編成、A/B切り替え、移動・回転・削除・Undo、地形配置、プリセット保存・読込、布陣復元、戦闘、再戦、約2秒の終了待機を確認しました。縦390×844・横844×390の表示、GitHub Pages相当のサブパス、PWAインストール条件、オフライン再起動を検証しています。

50対50・100対100・300対300のシミュレーションと途中追加を検証。300対300＋壁・岩・丘では、勝敗まで障害物侵入0件でした。ゲームディレクター・エンジニア・UX・行動心理／経済学の各視点で操作導線をレビューし、主操作の分散とクイック編成の戻り導線を修正しています。Android実機でのインストール操作・実機性能は未確認です。

## v5の修正と検証

現在のコードを監査し、既存のSpatialGridとWebGL Instancingは維持しました。同じ敵への集中、味方の局所密集、到達不能な敵への固執、入力イベントの境界条件を修正しています。キャラの能力値は変更していません。戦場の「性能を見る」でCPU処理時間・Draw Callを確認できます。

50/100/300対戦を実際の戦闘処理で終了まで実行し、丘・岩・壁の侵入0件、途中追加、勝敗固定、再戦布陣復元を確認。全19種類の回帰テストも通過しました。v5ではブラウザ・Android実機・GPU性能・PWAのインストール実操作は再検証していません。入力と描画API発行数はテストダブルによる確認です。詳細と改修前後の数値はAUDIT-v5.mdを参照してください。
